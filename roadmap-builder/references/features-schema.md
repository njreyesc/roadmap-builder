# Схема features.json

Вход для `plan_features.py` — согласованный список фич с оценками фаз.
Планировщик сам раскладывает фазы по неделям и генерирует `roadmap.json`
для рендереров.

```json
{
  "title": "Roadmap: Агентская платформа Q3",
  "subtitle": "приоритеты согласованы 14.07",
  "start": "2026-07-20",
  "today": "2026-07-16",
  "sprint_weeks": 2,
  "capacity": {"analytics": 1, "dev": 4, "testing": 2},
  "features": [
    {
      "name": "Интеграция с IDP",
      "priority": 1,
      "owner": "Команда А",
      "services": ["IDP", "CTL"],
      "analytics": 2,
      "dev": {"sprints": 3, "people": 2, "who": "Петров"},
      "testing": {"weeks": 2, "who": "Сидорова"},
      "milestone": "Выход на КО"
    },
    {
      "name": "Лимиты ОФР",
      "priority": 2,
      "after": "Интеграция с IDP",
      "analytics": {"weeks": 1, "who": "Иванов"},
      "dev": {"sprints": 2}
    }
  ]
}
```

## Корень

| Поле | Обязательное | Описание |
|---|---|---|
| `title` | да | Заголовок roadmap |
| `subtitle` | нет | Подзаголовок |
| `start` | да | Дата старта планирования, ISO. Округляется к понедельнику |
| `end` | нет | Правая граница roadmap. По умолчанию — конец самой поздней фичи |
| `today` | нет | Дата линии «сегодня» |
| `sprint_weeks` | нет | Недель в спринте для оценок в спринтах. По умолчанию 2 |
| `capacity` | нет | Пропускная способность в ше: число — общий пул на все фазы; объект `{"analytics": N, "dev": N, "testing": N}` — независимые пулы (нет ключа — фаза без ограничения). Без `capacity` все фичи идут параллельно |
| `allow_gaps` | нет | `true` — разрешить разрывы между фазами фичи (жадный режим). По умолчанию `false`: фазы встык, фича сдвигается целиком |
| `features` | да | Список фич — в порядке приоритета, если нет поля `priority`. При заданном `capacity` порядок = приоритет в очереди за ресурсами |

## feature

| Поле | Обязательное | Описание |
|---|---|---|
| `name` | да | Название фичи (уникальное) — имя дорожки roadmap |
| `priority` | нет | Число; если задано хотя бы у одной фичи, список сортируется по нему |
| `owner` | нет | Ответственный (человек/команда) — в левой колонке под названием |
| `services` | нет | Массив дорабатываемых сервисов/систем |
| `start` | нет | Явная дата старта фичи (иначе — глобальный `start`) |
| `after` | нет | Имя фичи-предшественника: старт со следующей недели после её конца. Предшественник должен идти в списке раньше |
| `analytics` | * | Оценка фазы «Аналитика» (голубая полоса) |
| `dev` | * | Оценка фазы «Разработка» (оранжевая полоса) |
| `testing` | * | Оценка фазы «Тестирование» (сиреневая полоса) |
| `milestone` | нет | Строка (подпись) или `true` — планируемая веха ◇ в понедельник после последней фазы |

\* — хотя бы одна из трёх фаз обязательна. Фазы идут последовательно:
аналитика → разработка → тестирование, каждая со следующего понедельника
после предыдущей.

## Оценка фазы

Три формы:

- **число** — недель: `"analytics": 2`
- **`{"weeks": N, "people": M, "who": "...", "label": "..."}`** — недели
- **`{"sprints": N, "people": M, "who": "...", "label": "..."}`** — спринты (× `sprint_weeks`)

`people` — сколько ше занимает фаза в пуле капасити (по умолчанию 1); при
`people > 1` дописывается к подписи («3 спринта 2 ше»). `who` дописывается к
подписи полосы («3 спринта / Петров»), `label` полностью заменяет автоподпись.
Дробные оценки допустимы — полоса округляется вверх до целых недель (единица
сетки), в подписи остаётся исходная оценка.

## Планирование по капасити

Фичи обрабатываются в порядке списка и идут параллельно, пока влезают в
капасити пулов. **Фазы одной фичи не разрываются**: цепочка аналитика →
разработка → тестирование ставится встык и сдвигается целиком до первого
окна, где каждый пул свободен в свои недели, — аналитика не стартует раньше,
чем разработка сможет подхватить её без паузы. Сдвиги печатаются в сводке.
`capacity: 1` даёт строго последовательное выполнение; без `capacity` фичи
параллельны без ограничений.

`"allow_gaps": true` в корне включает старый жадный режим: каждая фаза
стартует в первый свободный понедельник по отдельности — фича может
разорваться (аналитика сделана, разработка ждёт пул).

## Ограничения

- Явные `after`/`start` — нижняя граница старта фичи, капасити может сдвинуть
  её позже, но не раньше.
- Перекрытие фаз внутри фичи не поддерживается — фазы строго последовательны.
  Если нужен нахлёст, правь сгенерированный `roadmap.json` руками.
